# CEED BP1 / BP3 on cell-wise storage with flexible CG

The communication-free flexible CG of Wichrowski, "Coalesced Matrix-Free Finite Elements
in Cell-Wise Storage" (arXiv 2607.02335, Algorithm 1), with the CEED benchmark operators
generated by MARSIR from four-line specs.

- Operators: `marsir-compiler/specs/bp1.op` (mass, `v = g0*u`) and `bp3.op` (Laplacian,
  `dv = G du`, G the symmetric w det J J^-1 J^-T), `form = galerkin`, q = p + 2 Gauss
  points; PTX from `marsir-mlir/test/bp_gpu_pipeline.py` (cell-wise schedule), CPU gate
  `marsir-mlir/tools/emu_bp.cpp` against direct quadrature sums.
- Solver: `backend/distributed/unstructured/solvers/mars_cellwise_fcg.hpp`. x, p, z are
  continuous, r and q = A p unassembled; every scalar is a plain sum of a dual vector
  times a primal one (the paper's Lemma 1), so the DSS appears only in the
  preconditioner (DSS + Jacobi).
- Driver: `examples/distributed/unstructured/mars_marsir_bp.cu` (one GPU). Reference:
  `marsir-mlir/test/cellwise_bp_ref.py`.

## Correctness

numpy: cell-wise FCG and FCG on the assembled system give the same iterates (6e-16 over
25 iterations, BP1 and BP3); BP1 applied to 1 sums to the volume, BP3 applied to 1 is 0,
the BP3 element matrix is symmetric (1e-16), and the solve converges spectrally to the
manufactured solution (BP3 error 1e-4 at p = 3, 9e-6 at p = 5).

GPU (GH200, cstone 3a417b83): the FCG history equals the numpy one to every printed
digit (BP1 p = 3: 17 iterations; BP3 p = 3, 7, 1: 45, 71, 17), and every run passes
its checks (volume, null space, first elements against host quadrature, x = u).

## Throughput

GH200, one GPU, 16.8M element-local DoFs at every degree, deform 0.05, unique DoFs
(ne p + 1)^3. GB/s counts u, y and the stored geometry (1 value per Gauss point for BP1,
6 for BP3).

| GDoF/s per unique DoF | p = 1 | p = 3 | p = 7 |
|---|---|---|---|
| BP1 operator | 4.62 (1552 GB/s) | 18.9 (1395) | 15.6 (627) |
| BP3 operator | 1.00 (1384 GB/s) | 6.55 (1678) | 5.37 (667) |
| DSS (unstructured gather) | 1.32 (165 GB/s) | 22.0 (821) | 91.0 (2145) |
| BP1 operator + DSS | 1.02 | 10.3 | 13.2 |
| BP3 operator + DSS | 0.56 | 5.12 | 5.04 |
| FCG + DSS-Jacobi iterations, BP1 / BP3 | 18 / 307 | 6 / 770 | 6 / 1225 |
| FCG iteration, BP1 / BP3 | 2.84 / 4.44 ms | 1.48 / 2.07 ms | 1.60 / 2.89 ms |

The paper (A100, 2.0 TB/s) reports for the whole mass operator on a general geometry
with its unstructured DSS path (Table 7): 2.7 / 12.3 GDoF/s at p = 1 / 3, and 16.0 at
p = 6. Our BP1 operator + DSS is below that on a GPU with about twice the bandwidth, so
there is headroom:

- DSS at p = 1: 165 GB/s. The hand unstructured gather runs one warp per element, and a
  p = 1 element has 8 values.
- The p = 7 operators: 627-667 GB/s. The generic cell-wise schedule keeps every sweep
  stage in shared memory (BP3: 42 KB per element), one warp per element.
- FCG: the iteration is 1.7-2x the operator + DSS. The vector updates and pairings are
  separate passes.
- BP3 iterations grow with the mesh and the degree under Jacobi, as expected; a
  multigrid preconditioner is the companion paper's step.

## DSS: MARSIR-generated against the hand gather

`--dss-ptx` (the DSS generated from `mir.dss`, bit-identical; every FCG history is the
same as with the hand gather). At p = 1 the generated kernel packs 16 elements into a
128-thread block, 8 lanes each; the hand gather uses a warp per element. At p = 3 both
use a warp per element.

| | p = 1 hand | p = 1 generated | p = 3 hand | p = 3 generated |
|---|---|---|---|---|
| DSS | 1.63 ms, 165 GB/s | 0.48 ms, 555 GB/s | 0.33 ms, 815 GB/s | 0.42 ms, 636 GB/s |
| BP1 operator + DSS (GDoF/s) | 1.03 | 2.28 | 10.2 | 8.98 |
| BP3 operator + DSS (GDoF/s) | 0.56 | 0.81 | 5.10 | 4.78 |
| FCG iteration, BP1 / BP3 | 2.85 / 4.45 ms | 1.64 / 3.26 ms | 1.49 / 2.05 ms | 1.60 / 2.14 ms |

So the generated DSS for p = 1 (3.4x) and the hand gather for p >= 3. The generated
kernel's 1.3x at p = 3 is the gap already measured at p = 7 (All-MARSIR form,
`cellwise_unstructured_dss.md`). BP1 p = 1 operator + DSS is now 2.28 GDoF/s, against
the paper's 2.7 (A100, Table 7, general geometry, unstructured DSS). In the BP1 p = 1
FCG iteration (1.64 ms), the operator takes 0.47 ms, the DSS 0.48 ms, and the vector
updates and pairings the remaining 0.69 ms (four passes, about 16 vector reads and
writes).
